# Inbox

- `transfer(value)` for `@seroval/rpc/post-message` (from rpc-endpoint, 2026-11-11). JSON mode serializes buffers into the message, so a buffer never reaches `postMessage` as is. It needs a seroval plugin that keeps the buffer in the value and a transfer list from the writer. Removed from the API until then. Priority: later, until a consumer asks.
- Bound the queue of calls that wait for `serve` (from rpc-endpoint). Decided 2026-11-12: unbounded in rpc-0.1 and documented as a limit. Priority: later, until a consumer asks.
- Two streams in one value (`[g1, g2]`) failed with `Malformed node type "4"` (from rpc-streaming, 2026-11-11). Fixed by 0d5c5907 (seroval 1.8.1): the deserializer now stores well-known symbols under their node id. Regression test: `packages/seroval/test/well-known-symbol-reference.test.ts`. Checked again on 2026-11-24 at 3405af61 in seroval, transport and rpc.
- Two plain async iterables in one value, read one after the other, stall at small windows (from the two-streams check, 2026-11-24). With 10 items each and the reader draining `a` before `b`, the call times out (5 s) at window 1 and 4 and passes at 16; native generators pass at every window. Likely cause, not yet confirmed in code: `b`'s items fill the shared window and return no credit until read, so the writer blocks while `a` waits. Decide per-stream windows or document that streams in one value must be read concurrently. "Cancel only when all streams ended" is still untested. Priority: decide before rpc-release-0.1.
